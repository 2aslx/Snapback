## 1. 왜 Snapback인가

| 문제 | Snapback의 해결 |
|---|---|
| 사진이 수천 장이라 원하는 사진을 스크롤로 찾기 어렵다 | **기억나는 대로 문장으로 말하면** AI가 찾아 준다 |
| 날짜·장소가 정확히 기억나지 않는다 | 흐릿한 단서("비 오는 날", "창가", "케이크")만으로 찾고, **AI가 질문을 하나씩 던져** 후보를 좁힌다 |
| 스크린샷·문서 속 정보는 다시 찾기 어렵다 | 이미지 속 **글자와 정보까지 읽어** 정리해 둔다 |
| 흩어진 사진을 모으는 게 번거롭다 | "신촌에서 먹은 음식 모아줘"처럼 말하면 **AI가 앨범을 만든다** |
| 사진만 있고 그때의 경험은 남지 않는다 | 사진에서 **기록(추억·장소·문서)** 을 만들어 그날의 경험을 남긴다 |

## 2. 핵심 흐름

```
사진 분석  →  기억으로 찾기  →  사진 상세  →  기록 · 앨범 · 공유
                  ↑                │
                  └── 찾은 기억 학습 ┘
```

1. **사진 분석**: 사진마다 내용·장소 유형·인물·배경·날씨·시간대·글자를 AI가 뽑아 **기기 안의 텍스트 DB**에 저장합니다. 사진 원본은 복사하지 않습니다.
2. **기억으로 찾기**: 기억을 문장으로 말하면 가장 가능성 높은 사진을 크게 보여 주고, 필요하면 질문으로 후보를 좁힙니다.
3. **사진 상세**: 그날의 사진·비슷한 분위기의 사진을 묶어 보여 주고, 기록·앨범·공유로 이어집니다.
4. **찾은 기억 학습**: "맞아요"로 찾은 기억을 사진에 키워드로 남겨, 다음에는 더 빨리 찾습니다.

하단 탭: **사진 · 기억 · 기록 · 앨범**

## 3. 사진 가져오기 · 분석

> 내가 허용한 사진만, 빠르게 분석해 검색 가능한 텍스트로 바꿉니다.

**시작 · 초기 설정**
- 시작 화면(찰칵이 아이콘) → 시작 안내 → 사진 접근 범위 → 분석 순서 → 분석 시작.
- 시작 안내와 분석 순서 화면에 **"전체 접근을 허용해야 모든 사진을 분석할 수 있어요."** 를 굵게 안내합니다.
- 사진 접근 범위: **전체 사진**(실제 장수 표시) / **앨범 선택**(기기의 실제 앨범, 대표사진·장수) / **사진 직접 고르기** / **기간 지정**.
- 사진 직접 고르기: 사진 보관함 그리드, 아래로 내리면 자동으로 더 불러오기, **오른쪽 스크롤 바 + 촬영 날짜 말풍선**으로 빠르게 이동.
- 분석 순서: **오래된 사진부터(기본)** / 최근 사진부터 / **지정 기간 우선**(고른 연도를 먼저, 실제 사진이 있는 연도만 표시).
- 초기 설정을 마치면 다음 실행부터는 바로 홈으로 시작합니다.
- 웹은 파일을 골라 올리고, 브라우저에서 사진을 줄여(회전 반영) 보냅니다. 아이폰 사진(HEIC)도 변환해 올립니다.

**AI 사진 분석 (4가지 관점)**
- **시각**: 핵심 피사체, 색상·무늬·옷차림, 배경과 부수적 객체.
- **의미**: 이미지 유형(사진·스크린샷·문서·영수증·메뉴 등), 출처 플랫폼(확인될 때만), 카테고리, 핵심 주제, 요약.
- **정보 추출**: 이미지 속 핵심 글자, 유형별 구조화 정보(제품 목록, 시험 등급, 항목·수치 등).
- **라이프로깅**: 저장 목적 추정, 검색 키워드, 어울리는 기록 종류.
- 사람이 보이면 **주인공과 배경 인물을 구분**해 옷·행동을 구체적으로 적습니다. 신원은 추측하지 않습니다.
- 없는 가격·브랜드·수치는 만들지 않고, 보이지 않는 항목은 비워 둡니다("알 수 없음" 같은 문구를 남기지 않음).

**빠르고 정확하게**
- 1차는 **512px 저해상도로 여러 장을 동시에**(iOS 5장, 웹 2장) 분석합니다.
- 스크린샷·문서처럼 **글자가 많은 이미지는 1280px 고해상도로 한 번 더** 정밀 분석합니다.
- 사진은 자르지 않고 원본 비율 그대로 해상도만 낮춰 보냅니다.
- 이미 분석한 사진·앱에서 지운 사진은 다시 분석하지 않습니다. 한 번에 최대 300장.
- 서버가 잠깐 바쁘면 자동으로 다시 시도합니다.

**진행 상황 보기**
- **하단 진행 카드**: 찰칵이 + "사진 분석 중 · 36 / 300 · 12%" + 일시정지/이어하기. 다른 기능을 쓰면서 확인.
- **분석 진행 화면**: 진행률 원, 달리는 찰칵이, 남은 시간, 연도별 진행률, 분석된 사진 먼저 보기, **분석 취소**.
- **잠금화면 · 다이내믹 아일랜드 (iOS Live Activity)**: 앱과 같은 디자인으로 진행 표시, 완료되면 "분석 완료".
- 분석 개수는 **이번에 올린 사진만** 세고, 건너뛴 사진·실패한 사진을 따로 알려 줍니다.
- 앱을 껐다 켜도 남은 사진을 기억해 이어서 분석합니다(iOS). 백그라운드에서도 약 30초 동안 계속합니다.

## 4. 기억으로 찾기 (대화형 검색)

> "비 오는 날 창가에서 먹은 디저트"처럼 말하면, AI가 사진을 찾고 질문으로 좁혀 갑니다.

**검색**
- 기억을 문장으로 입력하면 **가장 가능성 높은 사진을 가로 폭에 맞춰 크게**(자르지 않음) 보여 주고, 장소·날짜·맞은 단서를 함께 표시합니다.
- 사진의 **시·구·동 주소**도 함께 보고 판단해 "신촌에서 찍은 …"처럼 장소로도 찾습니다.
- 1순위 사진 아래 **"다른 후보"에 일치도 60% 이상인 연관 사진을 모두 일치도 순으로 3열 바둑판**으로 보여 줍니다(60% 미만은 숨김).
- 일치도(점수)는 내부 기준에만 쓰고 **화면에는 표시하지 않습니다**.

- 다른 후보를 누르면 위로 크게 올라가고, "맞아요"로 확인합니다(원래 1순위는 아래로 내려와 다시 고를 수 있음).
- 다른 후보를 크게 본 뒤 **뒤로가기**를 누르면 홈이 아니라 바로 전에 보던 사진으로 한 단계씩 돌아갑니다.
- 홈에서 검색창을 누를 때마다 새 검색으로 시작하고, 검색창 밖을 누르면 키보드가 내려갑니다.
- 검색·앨범 만들기·기록 초안처럼 기다려야 할 때는 화면 맨 아래에 **얇은 진행 바**가 보입니다.

**질문으로 좁히기**
- **맞아요** → 사진 상세로 이동, 그 사진은 기억 탭에 저장됩니다.
- **질문 한 번 더하기** → 지금 후보들을 가장 잘 가르는 질문 1개를 AI가 만듭니다. 보기 2~3개, "기억 안 나요", **직접 입력**으로 답할 수 있습니다.
- 답한 단서는 사진 위에 태그로 쌓이고, **이미 물은 질문은 다시 묻지 않습니다**.
- 답하면 **그때 크게 보던 사진은 "아니다"로 보고 제외**한 뒤, **처음 검색의 상위 30개 후보 중 나머지 안에서만** 다시 찾습니다. 답할수록 제외된 사진이 쌓이고, 남은 후보가 없으면 새로 검색하도록 안내합니다.
- **이전 단계로 되돌리기**: 답을 잘못 눌렀거나 남은 후보가 0장이 되면, 처음부터 다시 검색하지 않고 직전 질문·후보·제외 상태로 돌아갑니다(서버 호출 없음).
- 사용자의 답이 사진 정보에 그대로 있는 사진(예: 답 "비" ↔ 날씨 비)을 먼저 세웁니다.

**언제 검색해도 같은 결과**
- 같은 검색(같은 문장·답·사진)은 **같은 결과**가 나옵니다. 자세한 방식은 [10. AI 정확도와 일관성](#10-ai-정확도와-일관성).

## 5. 찾은 기억 학습

> "맞아요"로 찾은 기억을 사진에 남겨, 쓸수록 내 말투에 맞춰 더 잘 찾습니다.

- "맞아요"(또는 후보를 골라 열기)를 누르면, 그때 쓴 기억 문장과 질문 답에서 **사진 분석이 놓친 정보를 키워드로 뽑아** 그 사진에 붙입니다.
  - 예: "작년에 친구 생일이라 연남동 카페에서 먹은 케이크" → `친구` `생일` `연남동`
- 화면은 바로 넘어가고 키워드는 뒤에서 받습니다(약 1초). 실패해도 검색 결과의 단서로 대신 붙입니다.
- **잘못된 기억이 섞이지 않게**
  - 사용자가 **실제로 말한 낱말만** 남기고, 이미 사진 정보에 있는 낱말·일반 낱말("사진", "먹은")은 뺍니다.
  - **사진 정보와 어긋나는 낱말은 붙이지 않습니다**(12월 사진인데 "여름", 카페 사진인데 "바닷가", 비 온 사진인데 "맑은").
  - **두 번 확인되면 확정**: 처음 나온 낱말은 '대기'로만 저장하고 검색에 쓰지 않습니다. **다른 검색**에서 같은 사진을 또 찾으며 같은 낱말이 다시 나와야 '확정'됩니다. 한 번 잘못 말한 낱말(친구와 갔는데 "엄마랑")은 검색에 영향을 주지 않습니다.
- **다음 검색에서**: 같은 문장으로 다시 찾거나, 확정 키워드가 2개 이상 겹치면 그 사진을 앞에 세웁니다.
- 다시 분석해도 키워드는 유지됩니다.

## 6. 사진 상세

> 찾은 사진에서 그날의 다른 사진, 사진 속 정보, 기록·앨범·공유로 이어집니다.

**관련된 추억**
- **그날의 사진**: 같은 날 찍은 사진(촬영 시각이 가장 가까운 사진이 대표).
- **비슷한 분위기**: 장소·배경·음식·키워드가 겹치는 사진. 카테고리나 의미 있는 키워드가 같아야 합니다(풍경이면 풍경, 음식이면 음식).
- 누르면 사진 모음으로 보고, **이 사진들로 앨범 만들기**로 바로 앨범을 만들 수 있습니다.

**사진 정보** (기본 접힘, 누르면 **스르륵 펼쳐짐**)
- **일반 사진**: 촬영 날짜·시간, 촬영 장소(시·구·동 주소), 주인공·배경 인물, 주요 장면, 분위기.
- **스크린샷·문서**: 이미지 유형, 출처, 핵심 주제, 주요 내용, 관련 키워드, **추출된 정보 미리보기**(예: 추천 제품 목록, 시험명·등급, 항목·수치).
- 감지되지 않은 항목("인원수 알 수 없음" 등)은 표시하지 않습니다.
- **지도 팝업**: 위치 정보가 있는 사진은 촬영 장소를 누르면 지도에 핀으로 표시합니다.
- **다시 분석하기**: 이 사진 한 장만 고해상도로 다시 분석해 바로 반영합니다.

**공유하기**
- iOS 공유 창(카카오톡·메시지·인스타그램 등). 사진 보관함의 원본을 그대로 넘겨 **복제본이 생기지 않습니다**.

## 7. 기록으로 남기기

> 사진 한 장에서 그날의 경험을 기록으로 정리합니다.

**기록 다듬기** — AI가 사진(문서면 글자까지)과 분석 정보로 초안을 만들고, 사용자가 확인·수정해 저장합니다.

| 기록 종류 | 담는 내용 |
|---|---|
| **추억 기록** | 제목, 날짜, 메모, 즐겨찾기 |
| **장소 기록** | 장소 이름, 위치, 방문 날짜, 장소 유형(카페·음식점·여행지·공원·자연·전시·공연·쇼핑), 메모, 즐겨찾기 |
| **문서 기록** | 문서 제목, 날짜, 추출된 주요 텍스트(항목: 값), 핵심 정보 요약, 개인 메모 |

- 세 가지 종류가 항상 나란히 보이고, AI가 추천한 종류가 선택된 채로 시작합니다.
- **민감정보**(건강·금융·신분증)가 감지되면 동의를 받아야 저장됩니다.
- 문서 속 이름·주민번호·전화번호·계좌번호 등은 옮겨 적지 않고, 요약에는 진단·조언을 넣지 않습니다.

**나의 기록** — 사진, 제목, 종류·날짜, 메모, 위치, **연결된 사진**(같은 날·가까운 곳에서 찍은 사진). 수정·삭제 가능.

**기록 탭**
- 기록을 카드로 모아 보고, **별**로 즐겨찾기(상단에 따로 표시).
- **정렬 기준**: 기본 / 장르별(추억·장소·문서로 묶어서) / 즐겨찾기 / 추억 기록 / 장소 기록 / 문서 기록.

## 8. AI 앨범 · 앨범 잠금

> 만들고 싶은 앨범을 말로 설명하면 AI가 사진을 모읍니다.

**흩어진 순간 모으기**
- 예: "신촌에서 먹은 음식 사진 모아줘", "올여름 먹은 것들", "홍대 사진 중 음식은 빼고", "따뜻한 분위기 사진".
- AI가 앨범을 만드는 3단계
  1. **요청 해석**: 장소·시간·주제·제외 조건으로 나눕니다. 장소는 행정동으로 펼치고(신촌 → 창천동·신촌동·대현동…), 시간은 날짜 범위로 바꿉니다.
  2. **장소·날짜로 정확히 거르기**: 사진 주소와 촬영 날짜로 서버가 거릅니다("성수동" ↔ "성수2가3동"도 맞음).
  3. **주제 판정**: 남은 사진을 AI가 판정하되, **근거가 실제 사진 정보에 있는 사진만** 넣습니다.
- **분위기 요청**("따뜻한", "쓸쓸한")은 노을·조명·비·안개 같은 시각 단서로 판정하고, 스크린샷·문서는 뺍니다.
- 못 찾으면 이유를 알려 줍니다(그 지역 사진 없음, 위치 정보 없음 등).
- **제안 버튼**: 앱을 켤 때마다 내 사진을 바탕으로 AI가 앨범 제안 3개를 새로 만듭니다.

**앨범 미리보기 → 내 앨범**
- 바로 저장하지 않고, **모두 선택된 상태에서 뺄 사진만 해제**, 이름 수정, 카테고리(AI 추천 표시)를 고른 뒤 만듭니다.
- 앨범 카드는 대표사진 뒤로 사진이 겹쳐 쌓인 모양입니다.
- **카테고리**: 전체 / 추억 / 취향 / 작업 + 직접 추가·삭제.
- 앨범 상세: 제목을 눌러 바로 이름 바꾸기, 카테고리 변경, 삭제(확인 팝업). 앨범을 지워도 사진은 남습니다.
- 앨범은 앱 안에서만 묶고, 사진 앱에 실제 앨범을 만들지 않습니다.

**앨범 잠금**
- 앨범 상세에서 **앨범 잠그기** → 숫자 4자리를 두 번 입력.
- 잠긴 앨범은 목록에서 **대표사진·장수 대신 자물쇠**만 보이고, 열 때마다 **비밀번호 4자리**를 물어봅니다.
- 앨범 안에서 사진을 보고 돌아오면 열린 채로, 목록에서 다시 들어오면 다시 잠깁니다.
- 5번 틀리면 30초 동안 입력을 막습니다. 비밀번호를 잊으면 앨범만 지울 수 있습니다(사진은 그대로).
- 비밀번호는 저장하지 않고 암호화된 형태(salt + SHA-256 해시)로만 기기에 저장합니다.

## 9. 사진 탭 · 기억 탭 · 설정

**사진 탭 (홈)**
- 큰 안내 문구 "어떤 순간을 / **찾고 있나요?**"와 검색창.
- **다시 꺼내 볼 기억**: 지난해 같은 날 사진, 기록한 사진, 찾은 사진 등을 골라 매일 바꿔 보여 주는 큰 카드(제목은 "비 오는 날 성수동 카페"처럼 자동 생성).
- **월간 리캡 "N월의 나"**: 사진이 있는 가장 최근 달의 **가장 자주 간 동네 · 자주 먹은 음식 · 분위기·취향**을 요약한 카드. 버튼 한 번으로 **자동 앨범**(그 달 전체 / 자주 간 동네에서 / 자주 먹은 음식 모음)을 미리보기로 열어 다듬고 저장합니다. 검색할 일이 없을 때도 지난 한 달을 돌아보게 하는 카드로, 기기 안에서 계산합니다(AI 호출 없음).
- **모든 사진**(기본) / **접기**를 누르면 최근 9장.
- **정렬 기준**: **시간순**(찍은 날짜 최근순, 월별로 묶음) / **추가순**(앱에 최근 추가한 사진부터). 고른 기준은 저장됩니다.
- **편집**: 사진을 골라(전체 선택 가능) **앱에서만 지우기**. 사진 앱의 원본은 그대로이고, 지운 사진은 다시 분석하지 않습니다.
- ＋ 버튼으로 사진 추가(사진 접근 범위부터), 톱니바퀴로 설정.

**기억 탭**
- 검색으로 **찾은 사진**을 최근 순 갤러리로 모아 봅니다. 편집으로 기록에서 뺄 수 있습니다.

**설정**
- 연도별 사진을 검색에서 숨기기/보이기, 분석 순서 다시 선택.
- **사진 다시 분석하기**: 모든 사진의 설명을 최신 AI로 새로 만듭니다(진행 카드·잠금화면에 표시, 중지 가능). 앨범·기록·찾은 사진은 그대로.
- **앱 초기화**: 분석 정보·앨범·기록·찾은 사진·설정을 모두 지우고 처음 화면으로(사진 앱 원본은 그대로).
- 서버 주소 변경, 지도 출처 표시(© OpenStreetMap).

## 10. AI 정확도와 일관성

> 같은 질문에는 같은 답을, 근거 없는 사진은 빼도록 설계했습니다.

| 장치 | 검색 | 앨범 | 효과 |
|---|---|---|---|
| **AI 무작위성 끄기** (temperature 0 + seed 고정) | ✓ | ✓ | 같은 입력에 거의 같은 답 |
| **순서는 서버가 정함** (점수 → 실제 단서 수 → 사진 순서) | ✓ | | 비슷한 점수끼리 순서가 바뀌지 않음 |
| **근거 확인**: AI가 댄 근거 낱말이 실제 사진 정보에 있는지 서버가 확인 | ✓ (없으면 감점) | ✓ (없으면 제외) | 지어낸 근거로 엉뚱한 사진이 들어오지 않음 |
| **사용자 답 우선**: 답이 사진 정보에 그대로 있는 사진을 먼저 | ✓ | | AI가 답을 놓쳐도 맞는 사진이 위로 |
| **결과 저장**: 같은 검색·같은 앨범 요청은 저장한 결과를 다시 사용 | ✓ (최근 30개) | ✓ (최근 50개) | 같은 요청 = 같은 결과 |
| **일치도 기준**: 60% 이상인 연관 사진만 후보로 (점수는 표시 안 함) | ✓ | | 관련 없는 사진은 숨기고 연관 사진은 모두 보여 줌 |
| **넘긴 사진 제외**: 질문에 답하면 보고 있던 사진은 다시 나오지 않음 | ✓ | | 같은 사진이 반복해서 나오지 않음 |
| **새 사진만 다시 판정** (사진 정보가 바뀌면 다시) | | ✓ | 사진을 추가해도 기존 결과는 유지, AI 호출도 절약 |

**사진이 많을 때: 하이브리드 임베딩 검색**
- 사진을 분석할 때 설명을 **256차원 임베딩**(장당 약 1KB)으로 만들어 **기기에만** 저장합니다(iOS는 앱 파일, 웹은 IndexedDB). 서버·외부 DB에는 저장하지 않습니다.
- 사진이 **80장을 넘으면** 검색어 한 문장만 임베딩으로 바꿔, 기기 안에서 **코사인 유사도 + 키워드·주소·찾은 기억·날짜 보너스**로 상위 약 90장을 먼저 고른 뒤 AI에 보냅니다. "디저트" ↔ "마카롱", "강아지" ↔ "말티즈"처럼 **글자가 안 겹쳐도** 찾습니다.
- 아직 임베딩이 없는 사진은 키워드 점수와 최신순으로 함께 넣어 놓치지 않고, 예전 사진은 이미지를 다시 분석하지 않고 저장된 분석 텍스트로 **뒤에서 자동으로 채웁니다**(50장씩). 다시 분석하거나 기억 키워드가 확정되면 그 사진만 조용히 갱신합니다.
- 앨범 요청에 "~빼고" 같은 제외 조건이 있으면 넉넉히(300장) 고르고, 실제 제외는 서버·AI가 판정합니다. 검색어 임베딩을 못 받으면 키워드 선별로 대신합니다.
- 서버는 한 번에 최대 2,000장까지 받고, AI에는 최대 300장만 보냅니다.
- AI는 맞는 사진만 짧게 답하게 해, 사진이 많아도 응답 시간을 줄였습니다(1,200장 검색 약 5~30초).

## 13. 알려진 한계

- **사진이 아주 많을 때**: 1차 선별은 임베딩 유사도에 기대므로, 임베딩이 아직 채워지지 않은 사진이 많을 때(앱을 처음 업데이트한 직후 등)는 키워드가 안 겹치는 사진을 놓칠 수 있습니다. 분위기처럼 모호한 앨범 요청도 정확도가 떨어질 수 있습니다.
- **응답 시간**: OpenAI 상태에 따라 크게 달라지고, 서버 함수 제한(60초)을 넘으면 실패할 수 있습니다.
- **정밀 분석 비용**: 글자가 많은 이미지는 고해상도로 한 번 더 분석해 비용이 더 듭니다.
- **주소**: 위치 정보가 있는 사진만 장소로 찾을 수 있고, 무료 지도 서비스(초당 1건)라 사진이 많으면 처음에 시간이 걸립니다.
- **앨범 잠금**: 앨범만 가리는 기능이라, 그 사진은 사진 탭·검색에서는 그대로 보입니다.
- **백그라운드 분석**: iOS는 백그라운드에서 약 30초만 허락해서, 오래 잠그면 앱을 열 때 이어집니다.
- **iOS 배포**: 무료 개발자 서명이라 등록된 기기에서만 설치되고 7일 뒤 만료됩니다.
- **공개 주소**: 웹 주소를 아는 누구나 AI 기능을 쓸 수 있습니다.
