## 핵심 흐름

```
사진 분석 → 기억으로 찾기 → 사진 상세 → 기록 · 앨범 · 공유
```

1. **사진 분석**: 사진마다 캡션·장소 유형·인물 특징·배경·날씨·시간대를 AI가 뽑아 **기기 안의 텍스트 DB**에 저장합니다. 사진 원본은 복사하지 않습니다.
2. **기억으로 찾기**: "비 오는 날 카페에서 케이크 먹었던 사진"처럼 말하면 가장 가능성 높은 사진을 크게 보여 주고, 필요하면 질문을 하나씩 더해 후보를 좁힙니다.
3. **사진 상세**: 그날의 사진·비슷한 분위기의 사진을 묶어 보여 주고, 기록으로 남기거나 앨범으로 만들거나 공유할 수 있습니다.

## 화면별 기능

### 시작 · 초기 설정

| 화면 | 기능 |
|---|---|
| 시작 화면(스플래시) | 앱 아이콘(카메라 캐릭터 '찰칵이')을 흰 배경 가운데에 표시. iOS 실행 화면 → 앱 로딩 → 첫 화면까지 끊김 없이 이어짐. 웹도 같은 아이콘으로 로딩 표시 |
| 시작 안내 | 앱 소개와 "시작하기". 버튼 아래에 **"전체 접근을 허용해야 모든 사진을 분석할 수 있어요."**를 굵게 안내. **초기 설정을 마쳤거나 분석한 사진이 있으면 다음 실행부터는 바로 홈**으로 시작 |
| 사진 접근 범위 | **전체 사진**(실제 장수 표시) / **앨범 선택**(기기의 실제 앨범을 대표사진·장수와 함께 보여 주고 여러 개 선택, 빈 앨범은 숨김) / **사진 직접 고르기** / **기간 지정**(2022년 이후). 권한이 없으면 설정 열기 안내 |
| 사진 직접 고르기 (iOS) | 사진 보관함 그리드에서 눌러 선택. 아래로 내리면 자동으로 더 불러오기. **오른쪽 스크롤 바**를 끌어 빠르게 이동하고, 옆에 **지금 보이는 사진의 촬영 날짜**가 말풍선으로 표시 |
| 분석 순서 | **오래된 사진부터(기본)** / 최근 사진부터 / **지정 기간 우선**. 지정 기간 우선을 고를 때만 연도가 스르륵 펼쳐지고, **고른 범위에 실제로 있는 연도만** 표시. 고른 연도를 먼저, 나머지는 오래된 순으로 분석. '분석 시작' 아래에도 전체 접근 안내 |

- 웹에는 사진 보관함이 없어 파일 선택으로 사진을 올립니다. 브라우저 내장 기능으로 사진을 줄이고(회전 정보 반영), 브라우저가 못 읽는 아이폰 사진(HEIC)은 그때만 변환 라이브러리를 불러와 JPEG로 바꿉니다.

### 사진 분석

- **한 번에 최대 300장**을 분석하고, **이미 분석한 사진·앱에서 지운 사진은 건너뜁니다**(대기열 자리도 차지하지 않음).
- **분석 v2 (4가지 관점)**: 시각(핵심 피사체·색상·무늬) · 의미(이미지 유형·출처·카테고리·핵심 주제·요약) · 정보 추출(핵심 글자·유형별 구조화 정보) · 라이프로깅(저장 목적 추정·검색 키워드·어울리는 기록 종류).
  - 1차는 512px 저해상도 모드로 **5장씩 동시에**. 스크린샷·문서·영수증처럼 **글자가 많은 이미지면 1280px 고해상도로 한 번 더** 정밀 분석합니다.
  - 화면 UI(좋아요·댓글 버튼)는 무시하고, 플랫폼(유튜브 등)과 촬영 장소를 구분합니다. 없는 가격·제품명·수치는 만들지 않고, 건강 문서는 판단 없이 적힌 값만 옮깁니다.
  - 사람이 보이면 **주인공과 배경 인물을 구분**하고, 옷은 색상·종류·보이는 글자·무늬로 구체적으로 적습니다.
  - 서버가 잠깐 바쁘면 자동으로 최대 2번 다시 시도합니다.
- **분석 개수**: 분석할 때마다 **이번에 올린 사진만** 셉니다(이어하기는 같은 묶음). 이미 분석한 사진을 고르면 "N장은 건너뛰었어요"라고 알려 주고, 실패한 사진은 "실패 N"으로 따로 표시하며 홈에서 이유를 볼 수 있습니다.
- **하단 진행 카드**: 찰칵이 · "사진 분석 중" · "36 / 300 · 12%" · 주황 진행선 · 일시정지/이어하기 버튼. 다른 기능을 쓰면서 진행 상황을 볼 수 있고, 누르면 자세한 진행 화면이 열립니다. 완료 5초 뒤 사라짐.
- **분석 진행 화면**: 진행률 원, 달리는 찰칵이(진행·일시정지·완료 동작이 다름), 남은 시간, 연도별 진행률, 일시정지, 분석된 사진 먼저 보기, **분석 취소**(누르면 한 번 더 확인, 이미 분석한 사진은 유지).
- **잠금화면 · 알림 센터 · 다이내믹 아일랜드 (iOS Live Activity)**: 앱 하단 진행 카드와 같은 디자인으로 진행 상황 표시. 완료되면 "분석 완료"로 바뀌고 15분 뒤 사라짐.
- **앱을 껐다 켜도** 남은 사진을 기억해 '일시정지됨'으로 보여 주고, ▶를 누르면 남은 사진만 이어서 분석합니다(iOS).
- 앱이 백그라운드로 가면 iOS가 허락하는 동안(약 30초) 계속 분석하고, 그 뒤에는 "잠시 멈춤 · 앱을 열면 이어서 분석해요"로 표시합니다.

### 사진 탭 (홈)

- 상단: 찰칵이 로고 + **Snapback**, **＋**(사진 추가 → 사진 접근 범위부터), **톱니바퀴**(설정).
- 큰 안내 문구 "어떤 순간을 / **찾고 있나요?**".
- **검색창**: 누르면 그 자리에서 검색 화면으로 스르륵 내려가고, 뒤로 가면 다시 올라옵니다. 홈에서 열 때마다 **새 검색**으로 시작합니다.
- **다시 꺼내 볼 기억** 카드: 지난해 같은 날 찍은 사진 → 기록으로 남긴 사진 → 검색으로 찾은 사진 → 장소가 있는 사진 순으로 골라 매일 바꿔 보여 줌. 제목은 기록 제목 또는 "비 오는 날 성수동 카페"처럼 날씨 + 장소로 자동 생성.
- 기본으로 **모든 사진**(월별)을 보여 주고, **접기**를 누르면 **최근 사진** 9장만. 썸네일은 칸에 꽉 차게 표시합니다.
- **편집**: 사진을 골라 **앱에서만 지우기**(확인 팝업). 분석 정보·썸네일·앨범/기록/기억 연결만 지우고 **사진 앱의 원본은 그대로**. 지운 사진은 다시 분석하지 않습니다.

### 기억으로 찾기 (대화형 검색)

- 기억을 문장으로 입력하면 **가장 가능성 높은 사진을 크게**, 일치 확률·장소·날짜·맞은 단서와 함께 표시.
- **맞아요** → 사진 상세로 이동, 그 사진은 기억 탭에 저장.
- **찾은 기억 학습**: "맞아요"(또는 후보를 골라 열기)를 누르면, 그때 쓴 기억 문장과 질문 답에서 **사진 분석이 놓친 정보를 키워드로 뽑아 그 사진에 붙입니다**(예: "작년에 친구 생일이라 연남동 카페에서 먹은 케이크" → `친구` `생일` `연남동`).
  - 화면은 바로 넘어가고 키워드는 뒤에서 받습니다(약 1초). 실패하면 검색 결과의 '확인 안 된 단서'와 질문 답으로 대신 붙입니다.
  - 사용자가 **실제로 말한 낱말만** 남기고, 이미 사진 정보에 있는 낱말·일반 낱말("사진", "먹은")은 뺍니다.
  - 기억이 틀렸을 수 있어서 **사진 정보와 어긋나는 낱말은 붙이지 않습니다**(예: 12월 사진인데 "여름", 카페 사진인데 "바닷가", 비 온 사진인데 "맑은"). 계절·날씨·시간대는 서버가 규칙으로 한 번 더 거릅니다.
  - 붙은 키워드(최대 12개, 최근 것이 앞)와 마지막 기억 문장은 검색·앨범 때 사진 정보와 함께 보내고, **다음에 같은 문장이나 키워드 2개 이상이 겹치는 기억으로 찾으면 그 사진을 앞에 세웁니다**. 다시 분석해도 유지됩니다.
- **질문 한 번 더하기** → 지금 후보를 가장 잘 가르는 질문 1개를 AI가 생성. 보기 2~3개 + "기억 안 나요", 또는 **직접 입력**으로 답할 수 있음. 답은 기존 맥락에 더해져 순위를 다시 계산(검색을 처음부터 하지 않음).
- 답한 단서는 사진 위에 태그로 쌓이고, **이미 물은 질문은 다시 묻지 않습니다**.
- 질문에 답한 뒤에는 **처음 검색의 상위 30개 후보 안에서만** 다시 찾습니다. 사용자의 답이 사진 정보에 그대로 있는 사진(예: 답 "비" ↔ 날씨 비)을 먼저 세웁니다.
- **결과가 일정하게**: AI 무작위성을 끄고(temperature 0 + seed), 순위는 서버가 점수(5점 단위) → 실제 사진 정보에 있는 단서 수 → 사진 순서로 정합니다. AI가 댄 단서가 사진 정보에 없으면 감점합니다. 같은 검색(같은 문장·답·사진 정보)은 저장해 둔 결과를 그대로 보여 줍니다(최근 30개).
- 가장 유력한 사진은 **가로 폭에 맞춰 사진 전체**(비율 그대로, 자르지 않음)를 크게 보여 줍니다.
- 나머지 후보는 아래 "다른 후보"에 작게 표시. 가장 유력한 사진과 **카테고리나 키워드가 하나라도 같은 사진만** 보여 줍니다(풍경이면 풍경, 음식이면 음식).
- 사진 주소(시·구·동)도 함께 보내 "신촌에서 찍은 …"처럼 장소로도 찾을 수 있습니다.
- 사진 상세에서 뒤로 오면 결과가 그대로 남아 있고, 이전 검색이 늦게 도착해도 새 검색 결과와 섞이지 않습니다.
- 검색창 밖을 누르면 키보드가 내려갑니다.

### 사진 상세

- 사진을 **가로 폭에 맞춰 전체**(비율 그대로, 자르지 않음) 표시, 기록이 있으면 기록 제목 표시.
- **관련된 추억**
  - **그날의 사진**: 같은 날 찍은 사진. 촬영 시각이 가장 가까운 사진이 대표.
  - **비슷한 분위기**: 장소·배경·음식·키워드 단서가 겹치는 사진. 단, **카테고리(풍경·음식·인물·정보성 이미지)나 의미 있는 키워드가 하나는 같아야** 합니다(날씨·시간대만 같은 사진은 제외). 유사도가 가장 높은 사진이 대표. (문서 기록이면 "비슷한 문서")
  - 누르면 해당 사진들을 그리드로 보는 화면이 열리고, 사진을 누르면 상세로, 뒤로 가면 원래 사진으로 돌아옵니다.
  - **이 사진들로 앨범 만들기**: 기준 사진 + 관련 사진으로 앨범 미리보기를 열어 이름(예: "10월 15일 비 오는 날 성수동 카페")·카테고리를 다듬고 저장.
- **사진 정보** (기본 접힘, 눌러서 펼치기) — 이미지 유형에 따라 다르게 보여 줍니다.
  - **일반 사진**: 촬영 날짜·시간 / 촬영 장소 / **주인공 · 배경 인물**(새 분석) / 주요 객체·장면 / 분위기·특징
  - **스크린샷·문서 등 정보성 이미지**: 저장 날짜 / 이미지 유형 / 출처(확인될 때만) / 핵심 주제 / 주요 내용 / **관련 키워드 칩** / **추출된 정보 미리보기**(예: 추천 제품 목록, 시험명·등급, 항목·수치). 위치 정보가 없으면 촬영 장소 줄 자체를 숨깁니다.
  - **다시 분석하기**: 이 사진 한 장만 1280px 고해상도로 다시 분석해 카드와 기기 DB에 바로 반영합니다(예전 방식으로 분석된 사진은 안내 표시).
  - 촬영 장소는 좌표 대신 **시·구·동 주소**(예: 서울특별시 성동구 성수2가3동)로 표시
  - "인원수 알 수 없음", "특정 복장 없음"처럼 **감지되지 않은 항목은 표시하지 않음**
  - 긴 문장은 **단어 단위로 줄바꿈**(한글이 글자 중간에서 끊기지 않게)
  - **위치 정보가 있는 사진**은 촬영 장소를 누르면 **지도 팝업**(핀으로 촬영 위치, 확대·이동 가능)
- **공유하기**: iOS 공유 창(카카오톡·메시지·인스타그램 등)을 띄웁니다. 앱은 사진을 복사해 두지 않으므로 **공유하는 순간 사진 보관함의 원본**을 넘기며, 갤러리에 복제본이 생기지 않습니다. 웹은 저장된 1080px 미리보기를 공유.
- **기록으로 남기기** / 이미 기록했다면 **나의 기록 보기**.

### 기록 (기록으로 남기기)

- **기록 다듬기**: AI가 사진(문서면 글자까지)과 분석 정보를 보고 초안을 만들고, 사용자가 확인·수정해 저장.
  - **장소 기록**: 장소 이름, 위치, 방문 날짜, 장소 유형(카페·음식점·여행지·공원·자연·전시·공연·쇼핑·기타), 메모, 즐겨찾기
  - **문서 기록**: 문서 제목, 날짜, 추출된 주요 텍스트(항목: 값), 핵심 정보 요약(AI), 개인 메모
  - **추억 기록**: 제목, 날짜, 메모, 즐겨찾기
  - 기록 종류(추억 · 장소 · 문서) 세 가지가 항상 나란히 보이고, AI가 추천한 종류가 선택된 채로 시작해 직접 바꿀 수 있음
  - **민감정보**(건강·금융·신분증)가 감지되면 동의 상자가 뜨고, 체크해야 저장 가능. 동의 날짜도 기록
  - 문서 속 이름·생년월일·주민번호·주소·전화번호·계좌번호는 **옮겨 적지 않으며**, 요약은 문서 내용만(진단·조언 없음)
- **나의 기록**: 사진(즐겨찾기 표시, ⋮ 메뉴: 기록 수정·사진 보기·기록 삭제), 제목, 유형·날짜, 메모, 위치·날짜·장소 유형, **연결된 사진**(같은 날·1.5km 안에서 찍은 사진, 3장 넘으면 +N).

### 기억 탭

- **찾은 사진**: 검색으로 찾은 사진을 최근 순 갤러리로. 누르면 사진 상세, 뒤로 가면 기억 탭.
- **편집**: 찾은 사진 기록에서 빼기(사진은 지워지지 않음).

### 기록 탭

- 기록으로 남긴 사진을 카드(사진 · 제목 · 종류·날짜)로 모아 봅니다. 카드를 누르면 나의 기록.
- 카드의 **별**을 누르면 즐겨찾기를 켜고 끕니다.
- 오른쪽 위 **정렬 기준**: 기본 정렬(즐겨찾기를 위에 따로) / 장르별 정렬(추억 · 장소 · 문서로 묶어서) / 즐겨찾기 / 추억 기록 / 장소 기록 / 문서 기록 — 고르면 그 기록만 보여 줍니다.

### 앨범 탭

- **흩어진 순간 모으기**: 만들고 싶은 앨범을 자연어로 설명하면 사진을 모아 줍니다. 예: "신촌에서 먹은 음식 사진 모아줘", "올여름 먹은 것들", "홍대 사진 중 음식은 빼고".
  1. AI가 요청을 **장소·시간·주제·제외 조건**으로 해석합니다. 장소는 주소에 나오는 행정 지명으로 펼칩니다(예: 신촌 → 창천동·신촌동·대현동·대신동·노고산동), 시간은 날짜 범위로 바꿉니다.
  2. 서버가 사진 **주소(시·구·동)와 날짜로 정확히** 거릅니다("성수동" ↔ "성수2가3동"도 맞음).
  3. 남은 후보 중 **주제·제외 조건**에 맞는 사진을 AI가 25장씩 나눠 `yes / maybe / no`로 판정하고, **AI가 댄 근거 낱말이 실제 그 사진 정보에 있는 `yes`만** 넣습니다.
  - **분위기 요청**("따뜻한 분위기", "쓸쓸한 느낌")은 사진 정보에 나올 시각 단서(노을·조명·비·안개 등)로 바꿔 판정하고, 스크린샷·문서 같은 정보 이미지는 뺍니다.
  - **같은 요청은 같은 결과**: AI 무작위성을 끄고(temperature 0 + seed), 해석한 조건과 사진별 판정을 앱에 저장해 다음에 다시 씁니다(최근 50개). 새로 추가했거나 다시 분석한 사진만 새로 판정합니다.
  - 못 찾으면 이유를 알려 줍니다(예: 그 지역 사진 없음, 위치 정보가 있는 사진 없음).
  - 장소로 찾을 수 있도록 위치 정보가 있는 사진의 주소를 **뒤에서 미리 받아 둡니다**(앱 시작·분석 후, 가까운 사진끼리 공유).
  - **제안 버튼**: 앱을 켤 때마다 **내 사진 DB를 바탕으로 AI가 새로 만든 제안 3개**(✦ 표시). 사진이 없거나 서버에 연결되지 않으면 기본 예시.
- **앨범 미리보기**: 바로 저장하지 않고 사진 확인·원하지 않는 사진 선택해 빼기·이름 수정·카테고리 선택(AI 추천 표시) 후 생성.
- **내 앨범**: 대표사진 뒤로 사진이 겹쳐 쌓인 앨범 카드(이름 · 사진 N장).
  - **카테고리 필터**: 전체 / 추억 / 취향 / 작업 + **사용자 정의 카테고리 추가·삭제**. 카테고리가 없는 예전 앨범은 전체에서 표시.
- **앨범 상세**: 사진 그리드, **제목을 눌러 그 자리에서 이름 바꾸기**, 카테고리 변경, **앨범 삭제(확인 팝업)**. 앨범을 지워도 사진·분석 정보는 남습니다.
- **앨범 잠금**: 앨범 상세에서 '앨범 잠그기' → 숫자 4자리를 두 번 입력. 잠긴 앨범은 목록에서 대표사진·장수 대신 자물쇠만 보이고, 열 때마다 비밀번호를 물어요.
  - 앨범 안에서 사진을 봤다가 돌아오면 열린 채로, 앨범 목록에서 다시 들어오면 다시 잠깁니다. 5번 틀리면 30초 동안 입력을 막습니다.
  - 비밀번호는 저장하지 않고 무작위 salt + SHA-256 해시만 기기에 저장합니다. 잊으면 찾을 수 없고 '비밀번호를 잊었어요'로 앨범을 지울 수 있습니다(사진은 그대로).
  - 앨범만 가리는 기능이라, 그 사진은 사진 탭·검색에서는 그대로 보입니다.
- 앨범은 앱 안에서만 묶여 있고, **사진 앱에 실제 앨범을 만들지 않습니다**.

### 설정

- **접근 범위(연도별)**: 연도별 사진을 검색에서 숨기기/보이기.
- **분석**: 백그라운드 분석, 분석 순서 다시 선택.
- **사진 다시 분석하기**: 이미 분석한 모든 사진의 설명(캡션·장소 유형·인물·배경·날씨·시간대)을 최신 AI로 새로 만듭니다.
  - 두 번 눌러 시작, 중지 가능. 사진 id·날짜·위치와 앨범·기록·찾은 사진은 그대로.
  - 진행 상황은 설정 화면과 **하단 진행 카드("사진 다시 분석 중")**, 잠금화면에 표시. 하단 카드를 누르면 설정으로, X를 누르면 중지.
- **서버**: API 서버 주소 변경(비우면 기본 서버). 서버·키에 문제가 있을 때만 경고 표시.
- 촬영 장소 주소 출처 표시(© OpenStreetMap).

### 디자인

- **디자인 B3 · 화이트 오렌지**: 흰 배경 + 주황(#F26B1D) 포인트, 카드·입력창은 아주 옅은 회색. 영문·숫자는 Inter, 한글은 iOS 기본 서체. 웹은 한글이 깨지지 않도록 자주 쓰는 한글 2,350자 글꼴(SnapbackKR, Pretendard 기반)을 앱에 넣었습니다.
- 화면 위에 떠 있는 **알약 모양 탭바**(사진 · 기억 · 기록 · 앨범), 선택한 탭은 연한 주황 배경.
- 캐릭터 **찰칵이**(카메라 몸통 + 렌즈 눈): 로고·진행 표시·앱 아이콘·잠금화면에 사용.
- 앱 아이콘 = 찰칵이, 앱 이름 = Snapback.
- 화면 전환: 앞으로 갈 때는 페이드, **뒤로가기 버튼은 화면이 오른쪽으로 밀리는 효과**. 뒤로가기 버튼은 넓은 터치 영역.
- 라이트/다크 모드 색상 대응.

## AI가 하는 일

| 기능 | 보내는 것 | 받는 것 |
|---|---|---|
| 사진 분석 | 512px 사진 1장 (저해상도). 글자가 많으면 1280px 한 장 더 (고해상도) | 이미지 유형·출처·카테고리·핵심 주제·요약·핵심 글자·구조화 정보·저장 목적·검색 키워드·기록 종류 + 캡션·음식·장소 유형·인물(주인공/배경)·배경·날씨·시간대 |
| 기억 검색 | 분석 텍스트 DB(주소·찾은 기억 키워드 포함) + 질문·답변 기록 | 후보 순위·맞은 단서, 다음 질문(중복 금지), 상위 30개 후보 |
| 찾은 기억 키워드 | 기억 문장 + 질문 답 + 그 사진의 분석 정보 | 사진에 붙일 새 키워드(낱말마다 사진 정보와 어긋나는지 판정) |
| 앨범 만들기 | ① 요청 문장 → ② 장소·날짜로 거른 후보 DB | ① 조건 해석(장소 지명·날짜 범위·주제·제외) ② 주제에 맞는 사진 목록, 앨범 이름, 추천 카테고리 |
| 앨범 제안 | 분석 텍스트 DB(주소 포함) | 앨범 요청 문장 3개 |
| 기록 초안 | 사진 1장(1280px, 글자 읽기용) + 분석 정보 | 기록 종류, 제목, 날짜, 장소, 추출 텍스트, 요약, 민감정보 여부 |

- 모든 프롬프트는 서버에 있고, 사람 이름·신원은 추측하지 않도록 지시합니다.
- 분석 결과의 **개인 식별 정보(성명·생년월일·전화번호·주민번호·이메일·계좌번호)는 서버가 한 번 더 지웁니다.** 성명으로 나온 이름은 캡션·요약에서도 지웁니다.
- 검색·앨범·제안 요청에는 구조화 정보를 빼고 긴 글은 잘라 보내, 요청 크기와 비용을 일정하게 유지합니다.

## 데이터와 개인정보

- **OpenAI API 키는 서버 환경변수에만** 있고 앱·브라우저로는 내려가지 않습니다.
- OpenAI 요청은 **`store: false`**로 보내 OpenAI에 저장되지 않습니다.
- 서버는 사진을 저장하지 않습니다. 분석·검색·기록 요청을 처리하고 바로 버립니다.
- 앱이 기기에 저장하는 것: 분석 텍스트 DB(분석 v2 필드, 찾은 기억 키워드 포함, 글자 발췌·구조화 정보는 길이 제한), 작은 썸네일, 사진 보관함 ID, 앨범, 기록, 찾은 사진, 카테고리, 주소 캐시, 지운 사진 목록. (웹은 1080px 미리보기를 브라우저 IndexedDB에 저장)
- 예전 방식(v1)으로 저장된 데이터도 그대로 읽히고, 사진별 "다시 분석하기"로 v2가 됩니다.
- **사진 원본은 복사하지 않고**, 화면 표시·공유·기록 초안이 필요할 때 사진 보관함에서 그때그때 읽습니다.
- 촬영 장소 주소는 좌표만 서버를 거쳐 지도 서비스(구글 지도 키가 있으면 구글, 없으면 OpenStreetMap)에 보내 받아옵니다.

## 로컬에서 실행

필요한 것: Node.js 20.6 이상, Flutter 3.50 이상, (iOS) Xcode

1. `.env.example`을 `.env`로 복사하고 키를 넣습니다. **`.env`는 절대 커밋하지 마세요.**

   | 변수 | 필수 | 설명 |
   |---|---|---|
   | `OPENAI_API_KEY` | ✓ | OpenAI API 키 |
   | `OPENAI_MODEL` | | 기본 `gpt-4o-mini` |
   | `PORT` | | 기본 `3000` |
   | `GOOGLE_MAPS_API_KEY` | | 있으면 촬영 장소 주소를 구글 지도로 변환 (없으면 OpenStreetMap) |

2. 웹 앱 + 서버

   ```bash
   cd flutter_app && flutter pub get && flutter build web --release && cd ..
   npm start            # http://localhost:3000
   ```

3. iOS 앱 (시뮬레이터 또는 기기)

   ```bash
   cd flutter_app && flutter run -d ios
   ```

   - VS Code에서는 F5로 실행됩니다(`.vscode/launch.json`).
   - iOS 앱은 기본으로 배포 서버(Vercel)를 씁니다. 다른 서버를 쓰려면 `--dart-define=SNAPBACK_API_URL=<주소>`를 붙이거나 앱 설정에서 바꿉니다.

## API

| 경로 | 하는 일 |
|---|---|
| `GET /api/health` | 서버·키 연결 확인 |
| `POST /api/analyze` | 사진 1장 분석 (`detail: "high"`이면 고해상도 정밀 분석). 분석 v2 필드 + 기존 필드 |
| `POST /api/search` | 기억 문장 + 질문·답변 기록 → 후보 순위(상위 10)와 다음 질문, 상위 30개 후보(`pool`) (`wantQuestion`이면 질문을 반드시 생성) |
| `POST /api/album` | 자연어 앨범 요청 → 조건 해석 · 주소/날짜 필터 · 주제 선택 → 앨범 이름, 사진 목록, 추천 카테고리, (못 찾으면) 이유, 다시 쓸 조건(`plan`) |
| `POST /api/suggest` | 사진 DB → 앨범 제안 문장 3개 |
| `POST /api/record` | 기록 초안 (종류·제목·추출 텍스트·요약·민감정보 여부) |
| `POST /api/place` | GPS 좌표 → 시·구·동 주소 |
| `POST /api/recall` | '맞아요'로 찾은 사진 + 기억 문장·질문 답 → 그 사진에 붙일 키워드 |

- IP당 분당 요청 제한(사진 분석 120회, 그 밖 30회), 요청 크기 제한, 60초 시간 초과, 로그의 키 가림 처리.

## 배포

### 웹 + 서버 (Vercel)

- 처음 한 번: vercel.com에서 이 저장소를 Import → Environment Variables에 `OPENAI_API_KEY`(선택: `OPENAI_MODEL`, `GOOGLE_MAPS_API_KEY`) 입력 → Deploy. 빌드 설정은 `vercel.json`에 있습니다.
- 이후 **`main`에 push하면 자동 배포**되고, 다른 브랜치는 Preview 주소로 배포됩니다.
- `.github/workflows/static.yml`(GitHub Pages 배포)은 자동 실행하지 않습니다. 필요하면 Settings → Pages에서 Source를 GitHub Actions로 바꾼 뒤 Actions 탭에서 직접 실행합니다.

### iOS 테스트 빌드 (GitHub Releases)

```bash
cd flutter_app
flutter build ipa --release --export-method development --build-number <번호>
```

- 빌드 번호는 `pubspec.yaml`의 `version`(예: `1.0.0+5`)으로 관리합니다.
- 개인(무료) Apple 개발자 팀으로 서명한 개발용 빌드라 **등록된 기기에서만 설치**되고 **7일 뒤 만료**됩니다.
- 여러 사람에게 배포하려면 유료 Apple Developer 계정으로 TestFlight·Ad Hoc 배포가 필요합니다.

## 알려진 한계

- **사진이 많을 때**: 검색·앨범·제안 서버는 한 번에 **2,000장**까지 받습니다(넘으면 앱이 최근 2,000장만 보냄). AI에는 최대 300장만 보내고, 300장이 넘으면 서버가 기억 문장·요청의 낱말이 사진 정보에 많이 나오는 사진부터 고릅니다. 그래서 낱말이 전혀 겹치지 않는 사진(예: "디저트"로 찾는데 사진 정보에는 "마카롱"만 있음)은 사진이 아주 많을 때 놓칠 수 있습니다. 분석은 한 번에 300장까지입니다.
- **정밀 분석 비용**: 글자가 많은 이미지는 고해상도로 한 번 더 분석해 장당 비용이 일반 사진보다 큽니다.
- **구조화 정보 검색**: 추출된 구조화 정보(제품 목록 등)는 아직 검색 요청에 보내지 않습니다(요약·키워드·글자 일부만 반영).
- **주소**: 위치 정보가 있는 사진만 장소로 찾을 수 있고, 주소는 OpenStreetMap 무료 서비스(초당 1건)로 받아 사진이 많으면 처음에 시간이 걸립니다.
- **HEIC (웹)**: 브라우저가 못 읽는 HEIC는 변환 라이브러리를 jsDelivr에서 그때 내려받습니다.
- **지도**: OpenStreetMap 공개 지도 서버는 가벼운 사용을 전제로 합니다. 사용자가 많아지면 Apple Maps(iOS)나 유료 지도로 바꿔야 합니다.
- **백그라운드 분석**: iOS는 백그라운드에서 약 30초만 허락해서, 잠금 상태가 길어지면 분석이 멈추고 앱을 열면 이어집니다.
- **공개 주소**: 웹 주소를 아는 누구나 AI 기능을 쓸 수 있습니다. OpenAI 사용량을 가끔 확인하세요.
- 잠금화면의 일시정지 버튼은 표시만 되고 누를 수는 없습니다.
